
# Contributing to Awesome Rust

Thank you for your interest in contributing to Awesome Rust!

Contributions are welcome and appreciated. This repository aims to maintain a curated collection of high-quality Rust frameworks, libraries, software, tools, and resources.

Before submitting a contribution, please read the guidelines below.

## What Can Be Contributed

You can contribute the following:

- Rust libraries and frameworks.
- Open-source software built with Rust.
- Developer tools for the Rust ecosystem.
- Rust-related learning materials and documentation.
- Useful resources for Rust developers.
- AI development tools and resources that support Rust development.

## Contribution Guidelines

Before submitting a project, make sure it meets the following requirements:

- The project is relevant to the Rust ecosystem.
- The project provides meaningful value to Rust developers.
- The project has clear documentation.
- The project has an accessible official website or source repository.
- The project is not already listed.
- The project is placed in the most appropriate category.

## Project Requirements

To maintain the quality and relevance of this list, submitted projects must meet the following requirements:

- **Minimum Stars:** GitHub repositories must have at least 1,000 stars at the time of submission.
- **Recent Activity:** Projects must show development activity within the last 6 months, such as code commits, releases, or meaningful code updates.
- **Project Status:** Projects must not be archived or abandoned.
- **Relevance:** The project must be directly related to Rust or its ecosystem.
- **Quality:** The project should provide useful functionality and a reasonable level of documentation.
- **No Duplicates:** Projects must not already be listed elsewhere in this repository.

Submissions that do not meet these requirements may be rejected.

## Writing Guidelines

Please follow these guidelines when adding a project:

- Use clear, concise, and objective English.
- Use the official project name.
- Write a short description explaining what the project does.
- Avoid promotional language and subjective claims.
- Use the official project website or repository link.
- Do not include unnecessary badges, emojis, or additional formatting.
- Follow the existing Markdown format.

### Entry Format

Use the following format when adding a project:

```markdown
- [Project Name](https://github.com/owner/project)
  - A concise description explaining the project's purpose and functionality.
```

### Example

```markdown
- [Axum](https://github.com/tokio-rs/axum)
  - An ergonomic and modular web framework built around Tokio and Tower.
```

## Categorization

- Add projects to the most relevant existing category.
- Avoid placing the same project in multiple categories.
- Do not create a new category for a single project unless there is a strong reason.
- Keep category descriptions short and informative.
- Follow the existing category structure and naming conventions.

## Adding a New Category

If you want to introduce a new category or subcategory:

- Make sure it represents a meaningful area of the Rust ecosystem.
- Check that it does not overlap significantly with existing categories.
- Provide a clear and concise category description.
- Update the Contents section in `README.md`.
- Maintain consistent naming and formatting.

Please explain the reason for introducing a new category in your pull request.

## Pull Request Guidelines

When submitting a pull request:

1. Make sure your contribution follows these guidelines.
2. Add the project to the appropriate section in `README.md`.
3. Update the Contents section if you introduce a new main category.
4. Check that all links are valid.
5. Ensure there are no duplicate entries.
6. Provide a clear and descriptive pull request title.
7. Explain what you are adding and why it belongs in this repository.

Please keep pull requests focused on a single improvement whenever possible.

## Review Process

All contributions are subject to review.

Maintainers may:

- Request changes or additional information.
- Suggest a different category.
- Reject projects that do not meet the contribution requirements.
- Edit descriptions for clarity and consistency.

Submitting a pull request does not guarantee acceptance.
