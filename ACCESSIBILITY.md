# Accessibility

Awesome Rust aims to make information about the Rust ecosystem accessible, understandable, and easy to navigate for everyone.

We recognize that people interact with documentation and online resources in different ways. This project is committed to improving the accessibility of its content and contribution experience.

## Accessibility Goals

We aim to:

- Keep documentation clear, readable, and consistently structured.
- Use descriptive headings to make information easier to navigate.
- Write meaningful link text that explains the destination whenever possible.
- Provide appropriate alternative text for meaningful images.
- Maintain sufficient readability across different screen sizes and display settings.
- Avoid relying solely on color, visual appearance, or decorative elements to communicate information.
- Keep contribution guidelines understandable and accessible to new contributors.

## Documentation Accessibility

The primary content of Awesome Rust is maintained in Markdown and displayed through GitHub.

When creating or updating documentation, contributors should follow these practices:

### Headings and Structure

- Use a logical heading hierarchy.
- Do not skip heading levels unnecessarily.
- Keep headings descriptive and relevant to their content.
- Use lists to organize related information clearly.

### Links

- Use descriptive link text whenever possible.
- Avoid ambiguous phrases such as "click here" or "read more" without additional context.
- Ensure links point to the intended destination.
- Prefer official project websites and documentation when available.

### Images and Media

- Include meaningful alternative text for informative images.
- Use empty alternative text for purely decorative images when appropriate.
- Avoid placing essential information exclusively inside images.
- Ensure visual elements do not replace important textual information.

### Tables and Formatting

- Use tables only when information benefits from a tabular structure.
- Provide clear column headings.
- Prefer simple Markdown formatting over unnecessarily complex layouts.
- Avoid using visual formatting as the only way to communicate meaning.

## Contributor Expectations

Contributors are encouraged to consider accessibility when submitting changes to this repository.

When updating the README or other documentation:

- Preserve a clear and consistent Markdown structure.
- Use descriptive headings and link text.
- Add appropriate alternative text to new informative images.
- Keep descriptions concise and easy to understand.
- Avoid unnecessary visual decorations and formatting.
- Check that new content remains understandable without relying on visual presentation alone.

Accessibility improvements are welcome through issues and pull requests.

Please also review our [Contributing Guidelines](CONTRIBUTING.md) before submitting changes.

## Known Limitations

Awesome Rust is a curated collection of external projects and resources. We do not control the design, accessibility, maintenance, or compatibility of third-party websites and applications listed in this repository.

Additionally:

- The accessibility of the GitHub interface depends on GitHub's own platform.
- External websites and documentation may have different accessibility limitations.
- This repository has not undergone a formal WCAG conformance audit.
- Comprehensive keyboard-only and screen-reader testing has not been established as part of the project's regular maintenance process.

We do not claim that every listed resource is fully accessible.

## Reporting Accessibility Issues

If you encounter an accessibility barrier in this repository, we welcome your feedback.

You can report an issue through:

- **GitHub Issues:** [Open an issue](https://github.com/abusofianid/awesome-rust/issues) describing the accessibility problem.
- **Email:** [abusofian.id@gmail.com](mailto:abusofian.id@gmail.com) for private or sensitive reports.

When reporting an issue, you may include:

- The affected file, section, or page.
- A description of the accessibility barrier.
- The steps needed to reproduce the problem, if applicable.
- The browser, assistive technology, or environment involved, if relevant.
- A suggested improvement, if you have one.

You do not need to disclose a disability or provide screenshots or recordings to report an accessibility issue.

Reports will be reviewed by the project maintainers, and appropriate improvements may be made based on the project's scope and available resources.

## Continuous Improvement

Accessibility is an ongoing effort.

We welcome suggestions, corrections, and contributions that help make Awesome Rust more inclusive and easier to use.

This document may be updated as the project evolves and its accessibility practices improve.

Thank you for helping make the Rust ecosystem more accessible to everyone.
